# Project documentation

All project documentation lives in this directory. Root `README.md` explains template use; this file maps durable product artifacts.

## Product definition

- `project-brief.md` — problem, audience, value, MVP, and success.
- `requirements.md` — confirmed product requirements and open questions.
- `backlog.md` — ordered work items.
- `features/` — independently deliverable behavior with stable acceptance IDs.

## Technical delivery

- `architecture.md` — current system structure and constraints.
- `decisions.md` and `adr/` — decision index and significant records.
- `plans/` — implementation plans linked to features.
- `test-strategy.md` — risk-based testing approach.
- `acceptance-matrix.md` — requirement-to-check traceability.
- `verification-report.md` — checks actually performed.

## Continuity and operations

- `project-state.md` — compact current-state recovery point.
- `handoffs/` — optional durable transfers between roles.
- `runbooks/` — local development, testing, container, deployment, and troubleshooting.

Copy templates rather than editing files named `_template.md`. Do not record PASS without running the check.
